# WorkBuddy 每日签到

**账号直连**版的 WorkBuddy 每日签到工具：一次授权，之后纯网络请求签到，
**不需要装 WorkBuddy 客户端、不需要它常驻**。

界面上只有三块：**账号授权 / 每日定时 / 消息推送**。
定时交给 Windows 计划任务，程序配好就能关，系统里零常驻。

## 特性

| 能力 | 说明 |
|---|---|
| **零依赖单文件** | PyInstaller 打成 onefile exe，目标机器不装 Python、不装任何库 |
| **不依赖客户端** | 令牌换好之后纯 HTTP 调接口，客户端装没装、开没开都不影响 |
| **自动续期** | access 约 28 天；过期前 5 天预刷新，遇到 401 再刷一次并重试 |
| **定时签到** | 界面里设时间 + 随机抖动，写进 Windows 计划任务，程序不用常驻 |
| **消息推送** | 企业微信 / 钉钉群机器人，只填 key，地址程序自动拼 |
| **三种授权方式** | 本机浏览器 / 链接推到手机 / 服务端授权后导入 |
| **全程零弹窗** | 连底层的子进程调用都不弹黑框 |

## 快速开始

### 方式一：直接用打包好的 exe

1. 从 [Releases](https://github.com/yehaia1/workbuddy-checkin/releases) 下载 `WorkBuddy签到.exe`
2. 放到一个**不会被随手删掉**的固定目录（例如 `D:\workbuddy-checkin\`）
3. 双击运行 → 第一次运行会在 exe 旁边生成 `config.json`
4. 「账号授权」点 **立即授权**，浏览器登录一次
5. 想自动签到 → 「每日定时」设时间 → **应用到系统**（然后程序可以关了）

> 定时任务里记录的是 exe 的绝对路径，**挪位置后要重新点一次「应用到系统」**。

### 方式二：从源码运行

需要 **Python 3.8+ 且带 tkinter**（官方 Windows 安装包默认包含）。本项目**零第三方依赖**：

```bash
git clone https://github.com/yehaia1/workbuddy-checkin.git
cd workbuddy-checkin
python checkin_gui.py
```

## 账号授权

签到接口要登录态。本工具走 **CodeBuddy CLI 的设备授权流程**换一份令牌：

1. 申请授权会话 → 拿到一条登录链接
2. 在浏览器（或手机）里登录并确认
3. 本机轮询到结果 → 令牌落到 `auth_oauth.json`

三条路，按你的场景选：

### A. 本机授权（默认，最省事）

点 **立即授权** → 自动打开浏览器 → 登录完窗口自己关掉。

### B. 推到手机

点 **推到手机授权** → 链接通过已配置的机器人发到你的企业微信 / 钉钉 →
手机上点开登录 → 本机在后台等着，拿到令牌后窗口自己关掉。

适合：目标机器没有浏览器、或者你人不在机器前。

### C. 服务端授权后导入

在服务器上跑 `wb_auth_server.py`（见[下一节](#服务端授权脚本适合人不在电脑前的场景)），
它会把链接发到手机、等着你扫码，最后输出一段 `WBAT1.…` 的**导入码**。
在本机点 **导入授权**，粘贴进去即可。

> **令牌只有一份。** `refreshToken` 每次刷新都会轮换，两台机器各存一份会互相踢掉
> （服务端返回 `12153`，表现为"授权莫名失效"）。所以服务端授权完**不留令牌**，
> 只给导入码；Windows 端导入后由它独占续期。

### 命令行等价操作

```bash
WorkBuddy签到.exe --auth                    # 本机浏览器授权
WorkBuddy签到.exe --auth-push               # 链接推到手机，本机等待
WorkBuddy签到.exe --import-token "WBAT1.…"  # 导入服务端授权结果
WorkBuddy签到.exe --pull-token <url> <secret>  # 从服务端一次性端口领取
WorkBuddy签到.exe --diagnose                # 看当前令牌状态（不显示令牌内容）
```

## 每日定时

### 三个角色分开

| 角色 | 负责什么 | 要不要一直开着 |
|---|---|---|
| **界面** | 设时间、写入系统、平时手动签到 | **不用**，配好就能关 |
| **Windows 计划任务** | 到点叫醒执行者 | 系统负责，零常驻 |
| **exe 无界面入口** | 真正执行签到，跑完退出 | 只在触发那一刻存在 |

### 怎么用

1. 点 **设置定时**
2. 勾「启用每日自动签到」，填时间（默认 `09:00`；多个用逗号分隔，如 `09:00, 21:00`）
3. 填随机抖动（默认 `±15` 分钟，`0` = 准点）
4. 点 **应用到系统**
5. 勾了「应用后自动关闭本程序」的话，界面会自己退出

### 必须知道的行为

| 情况 | 表现 |
|---|---|
| 关机 / 休眠错过时间点 | 已开启「错过后尽快启动」，开机后补跑一次 |
| 触发后耗时 | 首次约 1 分钟（含 exe 解包与安全软件扫描），之后更快 |
| 重复触发 | 签到接口幂等；任务也设了「不启动新实例」 |
| 权限 | 「当前用户 + 仅登录时运行 + 普通权限」，**不弹 UAC，不需要管理员** |

> 抖动用的是计划任务**原生 `RandomDelay`**，不是脚本里 sleep：到点前由系统自己在
> `09:00~09:15` 之间挑一个时刻触发。

## 消息推送

配置里**只填 key**，程序按官方域名自动拼完整地址：

| 渠道 | 你填什么 | 程序拼出什么 |
|---|---|---|
| 企业微信机器人 | webhook 链接 `?key=` 后面那段 | `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<key>` |
| 钉钉机器人 | 链接 `access_token=` 后面那段 | `https://oapi.dingtalk.com/robot/send?access_token=<token>` |

在「消息推送」里勾选渠道、填 key，点「发送测试」可验证。

> - 粘整条链接也能识别（自动抽出 key），但**推荐只填 key**。
> - 看着像链接却抽不出参数时程序会拒发，避免把消息误推到第三方地址。
> - 钉钉机器人若用「自定义关键词」，关键词需含「签到」二字（消息文案里已带）。
> - 两个渠道同时启用时，**一个失败不影响另一个**。

## 服务端授权脚本（适合人不在电脑前的场景）

`wb_auth_server.py` 在你自己的服务器上跑，零依赖，Linux / Windows 都行：

```bash
# 默认：生成链接 → 推到配置的渠道 → 等人扫码 → 输出一次性导入码
python3 wb_auth_server.py

# 全自动：授权后开一个一次性端口，Windows 端自己来取（推荐）
python3 wb_auth_server.py --handoff --port 8787
```

### 这个方案成立吗？

**成立，但要先想清楚令牌交给谁。** 两个关键事实：

1. `state` 只是服务端一段会话 id，`GET /v2/plugin/auth/token?state=xxx` 是**无状态轮询**
   ——谁拿着 `state` 谁就能取到令牌，跟发起请求的机器无关。所以"服务器生成链接、
   服务器轮询"在协议上没问题。
2. `refreshToken` 每次刷新都会**轮换**。两边各持一份 → 谁先刷新，另一份立刻失效。

所以本脚本的做法是：

| 模式 | 令牌落在哪 | 谁来续期 | 适不适合无人值守 |
|---|---|---|---|
| `--handoff` | 只落在 Windows 端 | Windows 端 | ✅ 全自动，推荐 |
| 默认（导入码） | 只落在 Windows 端（人工粘一次） | Windows 端 | 需要一次人工复制 |
| `--save-token <路径>` | 服务器**也**留一份 | 服务器 | ⚠️ 除非你就是要服务器签到，否则别用 |

脚本默认**不在服务器落盘**，拿到令牌只交出去、交完就不管了。
`--handoff` 模式的领取地址带一次性随机 secret，取走 2 秒后端口自动关闭。

### 前置条件

- 服务器能访问 `copilot.tencent.com`（授权接口）
- 服务器能访问企业微信 / 钉钉的机器人域名（否则收不到链接）
- `--handoff` 模式下 Windows 端要能访问到服务器的端口

配置直接用同一份 `config.json`（`push_channels` + key），也可以 `--config` 指定。

## 配置项

配置文件是 exe 旁边的 `config.json`（首次运行自动生成）。**通常不需要手改**。

| 键 | 默认 | 含义 |
|---|---|---|
| `push_channels` | `["wecom"]` | 推送渠道：`wecom` / `dingtalk`，可同时选；空数组 = 不推送 |
| `wecom_key` | `""` | 企业微信机器人 key（只填 key） |
| `dingtalk_key` | `""` | 钉钉机器人 access_token |
| `oauth_token_file` | `""` | 令牌文件路径。留空 = 程序目录下 `auth_oauth.json` |
| `oauth_auth_timeout` | `300` | 等待授权完成的最长秒数 |
| `schedule_enabled` | `false` | 是否已启用每日定时 |
| `schedule_times` | `["09:00"]` | 触发时间点列表 |
| `schedule_jitter` | `15` | 随机抖动分钟数，`0` = 准点 |
| `exit_after_apply` | `true` | 应用定时后自动关闭本程序 |

> ⚠️ **定时四项请用界面改**：改完还要同步进系统计划任务，只编辑这个文件不会生效。

> ⚠️ `config.json` 里存着你的机器人 key，`auth_oauth.json` 里是明文令牌，
> 两个都在 `.gitignore` 里。**不要提交、不要分享。**

## 从源码构建

```bash
# 1) 装 PyInstaller（装到本地隔离目录，不污染系统环境）
python -m pip install --target .build/pylibs pyinstaller

# 2) 一键打包
python build_exe.py
```

产物在 `dist/WorkBuddyCheckin.exe`，改名成 `WorkBuddy签到.exe` 也能跑。

`build_exe.py` 帮你避开一个**打包了才知道的坑**：打包用的解释器必须带 tkinter。
用不带 tkinter 的解释器打包，PyInstaller **不报任何错**，只是悄悄少收集
`_tkinter.pyd` 和 tcl/tk，exe 一启动就崩。脚本会自动挑一个带 tkinter 的解释器，
打完再跑一次自检，不通过直接报错。

## 常见问题

**Q：点按钮时冒出一个黑色的命令窗口？**
窗口程序自身没有控制台，去调 PowerShell 时 Windows 会给它新建一个控制台。
本工具所有系统调用都在隐藏窗口的方式下进行；有问题用
`tools/no_popup_check.py` 验证（详见 [docs/troubleshooting.md](docs/troubleshooting.md#点按钮闪出黑框)）。

**Q：提示「尚未授权」？**
本机还没有令牌。点「立即授权」（或「推到手机授权」/「导入授权」）。

**Q：提示「授权已失效」？**
`refreshToken` 也过期了（约 30 天没跑过，或服务端提前撤销）。重新授权一次即可。
如果是刚在服务器授权完又在本机导入了旧令牌，也会这样——令牌只能有一份。

**Q：定时到点了但没签到？**
打开程序看「每日定时」那行的系统状态；或用 `WorkBuddy签到.exe --sched-status`，
结果会写进 `checkin.log`。逐步排查见
[docs/troubleshooting.md](docs/troubleshooting.md#定时不生效)。

**Q：exe 挪了目录之后定时失效？**
任务里记的是绝对路径。打开程序，在「每日定时」里重新点一次「应用到系统」。

**Q：能不能不带界面跑？**

```bash
WorkBuddy签到.exe --run          # 签到一次（计划任务用的就是它）
WorkBuddy签到.exe --check-only   # 只看状态，不领
WorkBuddy签到.exe --test-notify  # 发测试消息
```
