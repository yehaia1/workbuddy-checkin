# 排查手册

## 第一步永远是：先做一次环境自检

打开程序，点界面上的「**环境自检**」按钮。它会依次检查：

- 客户端装没装、在不在跑（横幅里会显示检测到的安装路径）
- 宿主通道通不通
- 账号登录没登录（会**真连一次 IPC** 确认，这是唯一可靠的判据）

结果直接显示在顶部**横幅**和底部「**运行日志**」区里；
有问题时横幅会挂出醒目提示并直接给出处理按钮（打开客户端、重新自检等）。

完整日志写在 exe 旁边的 `checkin.log`（只有结果摘要，无敏感信息）。

## 点按钮闪出黑框

### 现象

点「定时签到」或其他按钮时，弹出一个 PowerShell 窗口。

### v1.5 已修复

原因和修法见 [architecture.md](architecture.md#子进程不弹控制台窗口)。简言之：
窗口程序自身没有控制台，拉起 `powershell.exe` 这类控制台程序时 Windows 会给它
新建一个控制台窗口；修法是所有子进程调用统一加
`creationflags=CREATE_NO_WINDOW` + `startupinfo(SW_HIDE)`。

如果你还想自己确认一遍（或者改了代码后想回归测试）：

```bash
python tools/no_popup_check.py
```

它会启动目标程序并**用 `EnumWindows` 枚举全系统可见顶层窗口**，
报告期间出现了几个控制台类窗口。`0` 表示安全。

### 自己写检查脚本时的坑

**不要只匹配 `ConsoleWindowClass`。** Win11 把控制台交给了 Windows Terminal 托管，
窗口类名变成了 `CASCADIA_HOSTING_WINDOW_CLASS`（还有 `OpenConsole.exe` 的
`PseudoConsoleWindow`）。只匹配一个类名会得出"没问题"的错误结论。

另外检查脚本本身要用 **`pythonw.exe`** 运行 —— 用 `python.exe` 的话它自带控制台，
子进程会继承控制台，**根本复现不出弹窗**。

## 定时不生效

按顺序查，基本上看完第 1 步就能定位。

### 1. 打开「定时签到」看系统状态

主界面点「**定时签到**」，对话框上方会显示一行**系统状态**：

| 显示内容 | 怎么看 |
|---|---|
| 任务名 | 正常情况下是 `WorkBuddyCheckin` |
| 状态 | `Ready` = 就绪；其他值会直接翻译成人话 |
| 触发时间 | 你设置的时间点（如 `09:00`） |
| 下次运行 | **已经加过抖动的具体时刻**（例如 `09:07`），不是整点 |
| 上次运行 | 上次的执行时间与结果，显示「成功」即为正常 |

如果这行提示「**任务指向的程序不是当前这个**」，说明 exe 被挪过位置，
点一次「**应用到系统**」即可修复。

### 2. 看程序里的运行日志

底部的「**运行日志**」区会记录每次执行的完整过程，右上角可以直接打开 `checkin.log`。
到点有没有真的跑过、跑出了什么结果，这里最清楚。

### 3. 手动点一次「立即签到」

和计划任务到点做的事完全一样（差别只是这次有界面）。
如果手动能签成功、定时不行，那问题就出在任务本身，回到第 1 步看系统状态。

### 4. 结果码翻译

「系统状态」行里显示的**上次运行结果不全是退出码**。`SCHED_S_*` 系列是**状态**，不是失败：

| 码 | 含义 | 算成功吗 |
|---|---|---|
| `0` | 成功 | ✅ |
| `2` | 未完成（客户端未就绪或未登录） | ❌ |
| `267009` | 正在运行 | ✅ |
| `267010` | 任务已被禁用 | ❌ |
| `267011` | **尚未运行过**（新建任务第一次触发前就是这个值） | ✅ |
| `267012` | 没有后续计划 | ❌ |
| `267013` | 任务被终止 | ❌ |
| `267014` | 就绪，尚未运行 | ✅ |

### 常见原因

| 症状 | 原因 | 处理 |
|---|---|---|
| 显示「任务指向的程序不是当前这个」 | exe 被挪走了 | 打开「定时签到」点一次「应用到系统」 |
| 到点完全没反应 | 触发条件要求"用户已登录"，锁屏或未登录时不触发 | 正常行为 |
| 错过了时间点 | 关机 / 休眠 | 已开 `StartWhenAvailable`，开机后会补跑 |
| 每次都是"未完成" | 到点时客户端没装 / 没登录 | 先在界面上点一次「环境自检」 |
| 提示"系统标记为异常" | 真实错误 | 结合「运行日志」与 `checkin.log` 定位 |

## 检测不到客户端 / 说我没登录

自检分了四层判断（[为什么这么设计](architecture.md#环境检测为什么要分两层)），
所以先看横幅说的是哪一句：

| 提示 | 含义 | 处理 |
|---|---|---|
| 客户端已安装，但当前没有运行 | 找到路径了，只是没开 | 点横幅上的「打开客户端并签到」 |
| 未找到 WorkBuddy 客户端 | 四处都没找到客户端程序 | 「设置 → WorkBuddy 客户端」手动指定，或点「自动检测」 |
| 在跑但通道没就绪 | 客户端刚启动，宿主通道还没建好 | 稍等再点「重新自检」 |
| **缺少内置模块** | 客户端装了，但它自带的内置模块没在预期位置 | 见下一节，通常点一下自检就好 |
| 在跑但没登录 | IPC 真连了一次，确认未登录 | 点「打开客户端」去登录 |

> 光看账号快照文件（`account-snapshot.json`）**不可靠** —— 登出后文件可能残留。
> 所以程序会**真的连一次 IPC** 来确认登录态。这是唯一可靠的判据。

## 提示"缺少内置模块"

**现象**：本机用得好好的，拷到另一台同样装了客户端、也登录了的电脑，
横幅却报「缺少内置模块，无法连接客户端」。

**原因**：客户端自带的内置模块，**在不同安装方式/版本下位置并不相同**——
有的是 `…/builtin/skills/library/`，有的是 `…/builtin-plugins/<插件>/skills/<名字>/`，
用户目录下的插件缓存又是另一套结构。旧版只认几条固定路径，一旦对不上就整体失效
（跟"没装客户端"看起来一模一样，实际不是）。

**v1.6 起**：程序不再依赖固定路径，而是**在候选目录里逐层去找**，
所以绝大多数情况升级后直接就好了。

万一还是提示缺模块：

1. 打开「**设置 → 内置模块目录**」，点「浏览…」。
2. 选中 `workbuddy_ipc` 所在的**父目录** —— 也就是打开后能看见一个名叫
   `workbuddy_ipc` 的文件夹、里面有 `__init__.py` 的那一层。
3. 保存后回到主界面，点一次「环境自检」。

> 常见的正确位置长这样（安装目录下）：
> `…\WorkBuddy\resources\app.asar.unpacked\resources\plugins\workbuddy-builtin\skills\library`
> 也常在用户目录里：
> `…\.workbuddy\plugins\cache\workbuddy-builtin\skill-library\<版本号>`

填错时保存会直接报错提醒，不会默默存进去。留空即恢复自动探测。

## 界面字太小

两步处理：

1. **先看程序有没有自动适配**。程序启动时会按系统缩放调整字号，
   正常情况下 250% 缩放下字不会变小。
2. **还嫌小就手动放大**：「设置 → 界面 → 显示缩放」可额外放大 10% / 25% / 50%
   （**需要重启程序生效**）。

如果手动放大后依然明显偏小，多半是 DPI 感知没生效，
原理见 [architecture.md](architecture.md#高-dpi为什么字会变小)。

## 签到失败

`checkin.log` 里会记一条 JSON，关键字段是 `result`：

| `result` | 含义 |
|---|---|
| `CLAIMED` | 领取成功 |
| `ALREADY_CLAIMED` | 今日已签到（**正常**，不是错误） |
| `NOT_ACTIVE` | 活动未开始 / 已结束 |
| `NOT_LOGGED_IN` | 未登录 |
| `CLIENT_NOT_RUNNING` | 客户端没运行 |
| `IPC_MODULE_NOT_FOUND` | 没找到客户端自带的内置模块（见上一节） |
| `IPC_ERROR` | 宿主通道调用失败 |

退出码约定：`0` 成功、`2` 环境问题（客户端缺失 / 未登录）、其他为异常。

> `result` 是 `ALREADY_CLAIMED` 时退出码依然是 `0`，计划任务不会标记失败。

## 推送没收到

1. 先点界面上的「**测试推送**」，它会向所有已配置渠道各发一条
2. 只填了 key 却收不到：
   - 企业微信：确认 key 是 webhook 链接 `?key=` 后面那段
   - 钉钉：确认是 `access_token=` 后面那段；若安全设置选了「自定义关键词」，
     关键词需包含「签到」二字（消息文案里已带）
3. 想确认程序拼出来的地址对不对：地址是按**官方域名**拼的，不接受自定义域名。
   看着像链接却抽不出参数时程序会**拒发**，避免消息被误推到第三方地址
4. 主界面配置摘要里的「推送」应显示已启用的渠道名（如「企业微信」）

## 打包相关

### 打包报错没有 pyinstaller

```bash
python -m pip install --target .build/pylibs pyinstaller
```

### 打出来的 exe 一启动就崩

按顺序怀疑：

1. **tkinter 没进包**。看体积：正常约 **11 MB**，只有约 **8 MB** 说明少了
   `_tkinter.pyd` 和 tcl/tk 运行时，是打包解释器不带 tkinter 导致的。
   v1.5 起 `build_exe.py` 会自动拦截并校验，正常情况下不会再出现。
2. **动态导入的依赖没进包**。症状是报 `ModuleNotFoundError: No module named 'hmac'`，
   并被误判成"客户端未登录"。用 `build_exe.py` 打包会自动带上这批 `--hidden-import`。

### 打包用的解释器

必须带 tkinter。可以用 `--python` 显式指定：

```bash
python build_exe.py --python C:\path\to\python.exe
```

> 有些环境的 Python 只有 `python3.exe` / `pythonw3.exe` 而没有 `python.exe`
> （例如通过非标准方式安装的精简版），此时 `py -3.13` 之类的写法不可用，
> 直接用实际存在的可执行文件路径即可。
